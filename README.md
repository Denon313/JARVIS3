# JARVIS 3.5 — GitHub Pages + Firebase

نسخه‌ی وب استاتیک؛ بدون Python و بدون API Key هاردکدشده. فایل‌ها را می‌توانی در یک repository قرار بدهی و از GitHub Pages منتشر کنی.

## فایل‌ها
- `index.html` — رابط کاربری و صفحه ورود
- `styles.css` — طراحی واکنش‌گرا، دارک، شیشه‌ای و انیمیشن Orb
- `app.js` — Firebase Auth، گفتگو، تنظیمات و مدیریت API
- `firebase-config.js` — فقط پیکربندی عمومی Firebase؛ باید مقداردهی شود
- `firestore.rules` — قواعد اولیه دسترسی Firestore
- `manifest.webmanifest` — مشخصات نصب وب‌اپ

## راه‌اندازی Firebase
1. در Firebase Console یک project بساز.
2. Authentication → Sign-in method → Google را فعال کن.
3. Authentication → Settings → Authorized domains، دامنه GitHub Pages خودت را اضافه کن؛ معمولاً `USERNAME.github.io`.
4. Firestore Database را بساز.
5. مقادیر Web App Config را در `firebase-config.js` جایگزین کن.
6. محتوای `firestore.rules` را در Firestore → Rules منتشر کن.
7. فایل‌ها را به GitHub push کن؛ در Settings → Pages شاخه‌ی اصلی و پوشه‌ی `/ (root)` را انتخاب کن.

## افزودن کلیدهای مدل
از Settings داخل اپ، کلیدهای Groq، Gemini یا API سازگار با OpenAI را وارد کن. چند کلید برای هر ارائه‌دهنده قابل ثبت است. سیستم در صورت خطای یک کلید، کلیدهای بعدی و سپس ارائه‌دهندگان دیگر را امتحان می‌کند.

**محدودیت امنیتی مهم:** این نسخه‌ی کاملاً کلاینتی برای نمونه‌ی اولیه است. کلیدهای AI در مرورگر کاربر ذخیره می‌شوند و برای صاحب دستگاه قابل مشاهده‌اند؛ از کلیدهای اصلی/حساس استفاده نکن. برای انتشار عمومی و استفاده‌ی واقعی، درخواست‌های AI باید از Firebase Cloud Functions یا سرور امن عبور کنند و کلیدها در Secret Manager نگهداری شوند. GitHub Pages به‌تنهایی بک‌اند یا محیط امن برای اسرار ندارد.

## محدودیت‌های واقعی نسخه وب
- Google Login از Firebase پشتیبانی می‌شود.
- حافظه گفتگوها با Firestore برای هر کاربر ذخیره می‌شود، اگر Rules و پیکربندی صحیح باشند.
- پنل فعلی مدیر فقط تشخیص حساب مدیر و اطلاعات پایه‌ی همان نشست را نشان می‌دهد. نمایش کامل فهرست ایمیل‌ها باید از یک Cloud Function امن با Firebase Admin SDK انجام شود؛ این قابلیت عمداً از کلاینت عمومی حذف شده است.
- وب‌سایت نمی‌تواند پس از بسته‌شدن صفحه، همیشه میکروفون را شنود کند یا به همه‌ی اپ‌ها، مخاطبین، تماس‌ها و پیامک‌ها دسترسی داشته باشد.
- فرمان‌های بازکردن اپ در این نمونه به لینک وب محدودند؛ اجرای واقعی برنامه‌ها، تماس‌گیری و خواندن/ارسال پیام‌ها به اپ اندروید بومی و مجوزهای صریح نیاز دارد.
- پیوست تصویر در این نسخه پیش‌نمایش دارد و هنوز به مدل بینایی ارسال نمی‌شود.
- لینک‌های جست‌وجو به Google Images، Google Search و Wikipedia باز می‌شوند؛ این نسخه نتایج گوگل را داخل برنامه scrape نمی‌کند.
- «Forwarder API» یک fallback بر اساس خطای درخواست است؛ تشخیص تعداد دقیق توکن/سهمیه باقی‌مانده فقط با داده‌ای که ارائه‌دهنده در اختیار می‌گذارد ممکن است. کلیدهای مختلف یک حساب لزوماً سهمیه‌ی جداگانه ندارند.
- سطح‌های کم/متوسط/زیاد روی پارامترهای درخواست اثر می‌گذارند، اما سهمیه یا مدل پولی را خودکار ایجاد نمی‌کنند.

## قبل از انتشار عمومی
- هیچ کلید هوش مصنوعی را در فایل‌ها، commitها یا GitHub Issues قرار نده.
- دامنه‌ی مجاز Firebase و قوانین Firestore را بررسی کن.
- برای محصول عمومی، API proxy امن و Cloud Function بساز؛ محدودیت نرخ، اعتبارسنجی ورودی، کنترل هزینه و لاگ امن اضافه کن.
- گزینه‌های میکروفون و حافظه باید با رضایت کاربر روشن شوند.
